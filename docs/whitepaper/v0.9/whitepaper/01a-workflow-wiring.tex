\section{Wiring KedgeFlow to Existing Agent Workflows}
\label{sec:wiring}

Figure~\ref{fig:workflow-wiring} places KedgeFlow beside an existing workflow. The harness---whether a command-line interface (CLI), software development kit (SDK), or graph runtime---owns models, memory, and planning. For protected targets like identity and access management (IAM) systems, the Agent Adapter submits tool proposals, the control plane supplies authority, and the gateway and resource adapter mediate effects.

These are logical roles and do not require cloud placement. A Governed Loopback Gateway can host enforcement on the workstation while the control plane remains independently protected locally or remotely (Section~\ref{sec:local-deployment}). Native runtimes may implement the Agent Adapter contract directly; a proxy or hook can provide an attachment point. The gateway and Grant Authority also share the atomic authority ledger specified in Section~\ref{sec:authority-ledger}. Complete mediation requires target controls to reject bypassing credentials and paths. Section~\ref{sec:interfaces} defines the six interfaces and the obligations at each endpoint.
